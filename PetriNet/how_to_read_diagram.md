# Як читати діаграму мережі Петрі

## Базові елементи

### 1. Позиції (Places) — кола ⭕

Позиції зберігають **токени** (фішки). Показують **стан** системи.

```
(● P_client)     — позиція з одним токеном
(●●● P_rooms)    — позиція з трьома токенами (пул)
(  P_found)      — порожня позиція
```

### 2. Переходи (Transitions) — прямокутники ▪️

Переходи виконують **дії**. Спрацьовують, коли на вході є всі необхідні токени.

```
┌─────────────┐
│  T_search   │  — перехід "Пошук"
└─────────────┘
```

### 3. Дуги (Arcs) — стрілки →

З'єднують позиції з переходами. Показують **рух токенів**.

```
Позиція → Перехід    (вхідна дуга: токен СПОЖИВАЄТЬСЯ)
Перехід → Позиція    (вихідна дуга: токен СТВОРЮЄТЬСЯ)
```

---

## Кольорове кодування

Кожен колір = окремий **актор** або **тип даних**:

| Колір | Що означає | Приклад |
|-------|------------|---------|
| 🔴 Червоний | Клієнт | P_client, P_found, P_confirmed |
| 🟢 Зелений | Готель/Номер | P_rooms, P_occupied |
| 🔵 Синій | Банк/Оплата | (не використовується окремо) |
| 🟡 Жовтий | Лічильник | P_attempts |
| ⚫ Чорний | Об'єднаний потік | P_hold, P_payment |

---

## Типи дуг

### Звичайна дуга (→)
```
P_client ──→ T_search
```
Означає: "T_search потребує токен з P_client щоб спрацювати"

### Пунктирна дуга (- - →)
```
T_search - - → P_rooms
```
Означає: "Токен повертається назад (не споживається остаточно)"

### Inhibitor arc (○─)
```
P_rooms ○── T_no_rooms
```
Означає: "T_no_rooms спрацює ТІЛЬКИ якщо P_rooms ПУСТЕ"

## Як читати потік

### Крок 1: Знайди початок
Шукай позиції з токенами (●). Це стартовий стан.

```
На початку:
• P_client: ●      (1 клієнт)
• P_rooms: ●●●●●   (5 номерів)
• P_attempts: ●●●  (3 спроби)
```

### Крок 2: Перевір активні переходи
Перехід **активний**, якщо ВСІ його вхідні позиції мають токени.

```
T_search потребує:
  • P_client: ● ✅
  • P_rooms: ● ✅
→ T_search АКТИВНИЙ (може спрацювати)
```

### Крок 3: Виконай перехід
Коли перехід спрацьовує:
1. Токени ЗАБИРАЮТЬСЯ з вхідних позицій
2. Токени ДОДАЮТЬСЯ у вихідні позиції

```
До:                     Після T_search:
P_client: ●      →      P_client: (пусто)
P_rooms: ●●●●●   →      P_rooms: ●●●●● (повертається)
P_found: (пусто) →      P_found: ●
```

## Спеціальні патерни

### 1. Об'єднання потоків (⭐)
Два окремих потоки зливаються в один:

```
P_found (🔴) ──┐
              ├──→ T_select ──→ P_hold (⚫)
P_rooms (🟢) ──┘

Клієнт + Номер → Об'єднаний токен
```

### 2. Розділення потоків (⭐)
Один потік розділяється на кілька:

```
                    ┌──→ P_confirmed (🔴)
P_paid (⚫) ──→ T_confirm ──┼──→ P_occupied (🟢)
                    └──→ P_email (🟢)

Об'єднаний токен → Клієнт + Номер + Email
```

### 3. Цикл повернення (🔄)
Токен повертається назад для повторної спроби:

```
P_payment ──→ T_pay_fail ──→ P_failed ──→ T_retry ──┐
     ↑                                              │
     └──────────────────────────────────────────────┘
```

### 4. Лічильник (🟡)
Кожне спрацювання зменшує кількість токенів:

```
P_attempts: ●●●  (3 спроби)
     │
     ▼
T_pay_fail (забирає 1)
     │
     ▼
P_attempts: ●●   (2 спроби залишилось)
```

### 5. Конкуренція переходів
Два переходи "змагаються" за один токен:

```
              ┌──→ T_search (якщо є номери)
P_client ────┤
              └──→ T_no_rooms (якщо немає номерів)

Тільки ОДИН з них може спрацювати!
```

## Приклад: Читаємо успішне бронювання

```
КРОК 0 (Початок):
┌────────────────────────────────┐
│ P_client: ●                    │
│ P_rooms: ●●●●●                 │
│ P_attempts: ●●●                │
│ Все інше: пусто                │
└────────────────────────────────┘
Активні: T_search

КРОК 1 (T_search):
┌────────────────────────────────┐
│ P_found: ●                     │  ← клієнт знайшов номери
│ P_rooms: ●●●●●                 │  ← номери ще не забрані
└────────────────────────────────┘
Активні: T_select

КРОК 2 (T_select):
┌────────────────────────────────┐
│ P_hold: ● (client+room)        │  ← об'єднано!
│ P_rooms: ●●●●                  │  ← -1 номер
└────────────────────────────────┘
Активні: T_to_payment, T_timeout

КРОК 3 (T_to_payment):
┌────────────────────────────────┐
│ P_payment: ● (client+room)     │
└────────────────────────────────┘
Активні: T_pay_success, T_pay_fail

КРОК 4 (T_pay_success):
┌────────────────────────────────┐
│ P_paid: ● (client+room)        │
└────────────────────────────────┘
Активні: T_confirm

КРОК 5 (T_confirm):
┌────────────────────────────────┐
│ P_confirmed: ● (client)        │  ← розділено!
│ P_occupied: ● (room)           │
│ P_email: ● (email)             │
└────────────────────────────────┘
Активні: T_cancel, T_checkout

ГОТОВО! Номер заброньовано.
```

## Приклад: Читаємо невдалу оплату

```
КРОК 0: P_payment: ●, P_attempts: ●●●

КРОК 1 (T_pay_fail):
  P_payment: ●  →  P_failed: ●
  P_attempts: ●●● → P_attempts: ●●  (мінус 1!)

КРОК 2 (T_retry):
  P_failed: ●  →  P_payment: ●  (назад!)

КРОК 3 (T_pay_fail знову):
  P_attempts: ●● → P_attempts: ●

КРОК 4 (T_retry знову):
  Повертаємось до оплати...

КРОК 5 (T_pay_fail втретє):
  P_attempts: ● → P_attempts: (пусто!)

КРОК 6 (T_reject):
  P_failed: ● → P_rejected: ●
  Номер повертається в P_rooms

КІНЕЦЬ: Спроби вичерпано.
```

## Швидка шпаргалка

| Символ | Значення |
|--------|----------|
| ⭕ з ● | Позиція з токеном |
| ⭕ без ● | Порожня позиція |
| ▪️ | Перехід |
| → | Дуга (токен рухається) |
| - - → | Дуга повернення |
| ○─ | Inhibitor (блокує якщо є) |
| 🔴 | Клієнт |
| 🟢 | Готель/Номер |
| 🟡 | Лічильник |
| ⚫ | Об'єднаний потік |
| ⭐ | Точка об'єднання/розділення |
| 🔄 | Цикл повернення |
